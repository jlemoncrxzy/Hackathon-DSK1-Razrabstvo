# ДСК · AI Sales Assistant

AI-помощник для отдела продаж строительной компании полного цикла. Система автоматизирует формирование коммерческих предложений на основе данных о ходе строительства, остатков материалов и текущих цен, а также берёт на себя часть работы с клиентскими ожиданиями. Проект вырос из задачи связать ERP-данные застройщика с реальной работой менеджера: вместо ручного сведения таблиц и подготовки КП менеджер получает готовое предложение с учётом фактических сроков сдачи, рисков поставок и изменений в проектной документации.

## Что умеет система

В основе лежит агентная архитектура. Отдельные модули отвечают за анализ хода строительства, генерацию персонализированных предложений, управление ожиданиями клиента при изменении сроков, поддержку менеджера при разборе диалогов и автоматический контроль лимитов скидок. Все эти сценарии работают поверх единой базы данных, которая имитирует ERP застройщика: графики производства ЖБИ, состояние площадок, остатки материалов, доступные квартиры, изменения в проекте и история обработанных диалогов с клиентами.

Пользовательский интерфейс построен на чистом HTML, CSS и JavaScript без React, Tailwind и сборщиков. Дизайн-система выдержана в единой оранжево-графитовой гамме с использованием стеклянных панелей, анимированных баннеров и кастомной SVG-системы иконок. Отдельно реализован интерактивный WebGL-фон, который адаптируется к роли пользователя и снижает нагрузку при уменьшении движения в системе.

## Технологический стек

**Бэкенд.** Ядро написано на **Python 3.11+** и **FastAPI**. FastAPI выбран за нативную асинхронность, автоматическую OpenAPI-документацию и удобную работу с WebSocket и SSE. Все эндпоинты разделены на три группы: чат-помощник, сервисные операции с корзиной и уведомлениями, а также универсальный мост `/workspace` и `/actions/{name}`, через который фронтенд получает нормализованные данные и отправляет действия пользователя.

**LLM.** В качестве языковой модели используется **GigaChat** от Сбера в конфигурации `GigaChat 3.5 Ultra`. Модель подключается через официальный SDK `gigachat`, а не через LangChain-обёртки — так проще контролировать таймауты и повторные попытки при нестабильной сети. GigaChat отвечает за генерацию текста коммерческих предложений, анализ диалогов, формирование рекомендаций менеджеру и поддержку диалога с клиентом. Промпты строго разделяют системный контекст и пользовательские данные, а ответы проходят через модуль `security.py`, который вырезает конфиденциальные упоминания (себестоимость, маржу, внутренние инструкции, ссылки на CRM).

**RAG.** Для доступа к базе знаний реализован полноценный RAG-пайплайн на **ChromaDB** с эмбеддингами от `sentence-transformers`. В индексе хранятся три типа документов: проекты (название, адрес, сроки, этап), квартиры (комнаты, площадь, этаж, цена, скидка) и обработанные диалоги (проблемы клиентов и решения менеджеров). При запросе пользователя система ищет топ-7 релевантных документов и передаёт их в GigaChat как контекст — так модель отвечает на основе реальных данных, а не общих формулировок.

**Кэш и индексация.** Данные ERP загружаются в память при старте приложения и обновляются через `/admin/reload`. Для быстрого поиска по диалогам используется **Whoosh** — лёгкий полнотекстовый движок, который не требует внешних сервисов. Векторный поиск идёт через ChromaDB. Такая связка даёт скорость чтения на уровне памяти и одновременно позволяет делать семантический поиск по большим текстам.

**Хранение.** Проект работает с локальными JSON-файлами в папке `backend/data`. Это решение осознанное: имитация ERP-данных, история диалогов, клиенты, корзина пользователя, сгенерированные предложения и уведомления лежат в отдельных файлах и легко заменяются на настоящую СУБД. Все операции чтения и записи проходят через модуль `user_data.py`, который безопасно обрабатывает пустые и повреждённые файлы.

**Фронтенд.** Чистый JavaScript без фреймворков. Вся логика разбита на небольшие модули: `app.js` — контроллер и роутинг, `api.js` — единственная точка обращения к бэкенду, `views.js` — шаблоны страниц, `panels.js` — модальные окна, `roles.js` — клиентский кабинет, `chat_bridge.js` — интеграция чата с бэкендом, `notifications_bridge.js` — система уведомлений. Дизайн-система описана в семи CSS-файлах с чётким разделением: типографика, интерфейс, кнопки, адаптивные раскладки, состояния движения.

## Архитектура

Мост между данными и фронтом реализован в `workspace_bridge.py`. Он нормализует идентификаторы (`P001` → `p1`, `A101` → `a1`), приводит даты к формату кварталов, гарантирует корректность всех полей и собирает единый JSON, который фронт ожидает как `DSK_DATA`. Все действия пользователя (создание КП, бронирование, сохранение клиента, анализ диалога) проходят через единый диспетчер `/actions/{name}`, что упрощает добавление новых операций без изменения фронтенда.

Сам чат-помощник использует RAG для формирования ответа и дополнительно извлекает из контекста идентификаторы квартир, чтобы под ответом появилась кнопка «Оформить КП» — она сразу открывает панель создания предложения с предзаполненными полями. Если RAG не вернул конкретных квартир, срабатывает fallback: система разбирает запрос по критериям (комнаты, бюджет, проект) и подбирает три подходящих свободных варианта.

Для запуска воспользуйтесь инструкцией, которая приложена в корне проекта.

- - - - - - -

Роли пользователей
В демо-режиме доступны три роли, переключаемые через профиль или горячие клавиши. Менеджер видит рабочее пространство отдела продаж: клиентов, каталог квартир, предложения, согласования, ход строительства и аналитику. Руководитель дополнительно может принимать решения по индивидуальным скидкам, превышающим лимит финансовой модели. Клиент получает отдельный кабинет с состоянием объекта, своими предложениями, поддержкой и встроенным чатом. Переключение - нажмите ЛКМ по вашему профилю в правой верхней части экрана, чтобы проявить выпадающий список.

Ограничения демонстрации
Проект создан как рабочий прототип, а не готовый продукт. Все данные в папке backend/data вымышлены, интеграция с настоящей ERP и CRM не подключена, отправка email и SMS не выполняется. Решения по резервированию квартир, согласованию скидок и уведомлениям хранятся локально и сбрасываются при очистке соответствующих JSON-файлов. Для перевода в продакшн потребуется подключить реальные источники данных, перенести хранилище в СУБД, настроить серверную авторизацию и добавить валидацию финансовых правил на бэкенде.
